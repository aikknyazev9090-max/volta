# ТЗ: Telegram-букмекер (демо-версия, без реальных денег)

> Документ для ИИ-агента-разработчика. Читай целиком до начала работы. У тебя есть доступ к терминалу, браузеру и компьютеру — используй браузер для изучения референсов и для проверки результата на каждом этапе.

---

## 1. Суть продукта

Букмекерская контора внутри Telegram: пользователь открывает бота, нажимает «Играть» и попадает в **Telegram Mini App** (веб-приложение внутри Telegram), где ставит на спорт **виртуальными монетами**.

- Валюта демо-версии — **монеты (🪙 BetCoins)**. Их нельзя купить, продать, вывести или обменять на что-либо ценное. Это важно юридически: без ценности монет это игра, а не азартная деятельность.
- Цель демо — показать продукт инвесторам/пользователям, обкатать механику ставок и расчёта, собрать аудиторию.
- Архитектура с первого дня закладывается так, чтобы потом подключить реальные деньги без переписывания ядра (см. раздел 10).

**Главный критерий приёмки — дизайн и ощущение от продукта.** Приложение должно выглядеть и ощущаться как топовое мобильное приложение 2026 года, а не как учебный проект: плавные анимации, продуманные состояния, ни одного «сырого» экрана.

---

## 2. Состав системы

| Компонент | Назначение |
|---|---|
| **Telegram-бот** | Вход, кнопка запуска Mini App, уведомления (ставка сыграла/проиграла, ежедневный бонус, начало матча из избранного), команды `/start`, `/balance`, `/help` |
| **Mini App (фронтенд)** | Весь интерфейс ставок |
| **Бэкенд API** | Пользователи, события, коэффициенты, ставки, расчёт, баланс |
| **Сервис линии** | Загрузка матчей и коэффициентов (реальные данные или генератор), симуляция лайва |
| **Админ-панель** | Управление событиями, ручной расчёт, маржа, пользователи, статистика |

## 3. Рекомендуемый стек

Можно отступить, если есть веская причина — опиши её в README.

- **Фронтенд:** React 18 + TypeScript + Vite, Tailwind CSS, Framer Motion (анимации), TanStack Query (данные), Zustand (купон ставок), `@telegram-apps/sdk-react` (интеграция с Telegram).
- **Бэкенд:** Node.js 20+, TypeScript, Fastify, Prisma, PostgreSQL (для локальной разработки допустим SQLite), Redis — опционально для лайва/кэша.
- **Бот:** grammY.
- **Реалтайм:** WebSocket (Fastify websocket или Socket.IO) — обновление коэффициентов и счёта в лайве.
- **Инфраструктура:** Docker + docker-compose (одна команда поднимает всё), `.env.example`, для разработки — туннель (cloudflared или ngrok), т.к. Mini App работает только по HTTPS.
- **Тесты:** Vitest (юнит, особенно расчёт ставок), Playwright (e2e основных сценариев).

## 4. Функциональность MVP

### 4.1. Вход и онбординг
- `/start` → приветствие с красивой картинкой/анимацией и кнопкой «🎯 Открыть» (Mini App).
- Авторизация только через Telegram `initData`, **подпись проверяется на бэкенде** (HMAC по токену бота). Никаких паролей.
- Новому пользователю — стартовый баланс **10 000 монет** и онбординг из 3 слайдов (как ставить, что такое экспресс, что монеты виртуальные).
- Плашка 18+ и «Демо-режим: ставки на виртуальные монеты» — ненавязчиво, но видно.

### 4.2. Главный экран
- Шапка: аватар, баланс с анимацией изменения (счётчик «прокручивается»), кнопка ежедневного бонуса.
- Переключатель **Лайв / Скоро / Все**.
- Горизонтальная лента видов спорта с иконками: футбол, хоккей, баскетбол, теннис, киберспорт (CS2, Dota 2), MMA, волейбол.
- Карусель «Топ-матчи» (крупные карточки с эмблемами команд, временем, тремя основными коэффициентами).
- Список матчей, сгруппированный по лигам (сворачиваемые группы, флаг страны, логотип лиги).
- Карточка матча: команды с логотипами, время/минута и счёт для лайва (пульсирующая красная точка LIVE), коэффициенты П1/Х/П2 — кликабельные прямо в списке.
- Поиск по командам и лигам.

### 4.3. Страница матча
- Хедер с командами, счётом, таймером, для лайва — простая визуализация (полоса давления/атак или мини-статистика: удары, угловые, владение).
- Рынки, сгруппированные во вкладки: **Основные / Тоталы / Форы / Голы / Тайм**:
  - Исход 1X2, двойной шанс
  - Тотал больше/меньше (несколько линий)
  - Фора (азиатская/европейская)
  - Обе забьют
  - Точный счёт (сетка)
  - Исход 1-го тайма
- Изменение коэффициента подсвечивается: рост — зелёная стрелка ↑, падение — красная ↓, с короткой анимацией.
- Заблокированный рынок (в лайве во время опасного момента) — иконка замка, затемнение.

### 4.4. Купон ставок (bet slip)
- Нижняя «шторка» (bottom sheet), всплывает при добавлении исхода, с бейджем количества.
- Режимы: **Ординар** и **Экспресс** (коэффициенты перемножаются). Несовместимые исходы одного матча в экспресс не добавляются — понятное сообщение.
- Ввод суммы + быстрые кнопки (100 / 500 / 1000 / Макс), расчёт потенциального выигрыша в реальном времени.
- Если коэффициент изменился до подтверждения — показать новый и попросить подтвердить (настройка «Принимать любые изменения / только повышение / не принимать»).
- Подтверждение ставки: haptic feedback, анимация «билет улетает» в историю, тост.
- Лимиты: мин. ставка 10, макс. ставка 50 000, макс. выигрыш 1 000 000, макс. 15 событий в экспрессе.

### 4.5. Мои ставки
- Вкладки: **Активные / Рассчитанные**.
- Карточка ставки в виде «билета»: события, коэффициент, сумма, возможный/фактический выигрыш, статус (в игре / выигрыш / проигрыш / возврат), для лайва — текущий счёт.
- Выигрыш — праздничная анимация (конфетти, без перебора).
- **Cash-out** (досрочный выкуп) — желательно; формула: `текущая вероятность × потенциальный выигрыш × (1 − маржа выкупа)`.

### 4.6. Профиль и удержание
- Статистика: всего ставок, процент выигрышей, ROI, крупнейший выигрыш, любимый вид спорта.
- **Ежедневный бонус** (стрик 7 дней, растущая награда) — главная механика возврата.
- **Таблица лидеров** (по прибыли за неделю / за всё время) — соревновательный элемент.
- Достижения/бейджи (первая ставка, экспресс из 5+, серия выигрышей и т.п.).
- Избранные команды/матчи → уведомление в боте перед началом.
- Реферальная ссылка: бонусные монеты обоим (через `start`-параметр бота).
- Если баланс упал до нуля — кнопка «Пополнить демо-баланс» (бесплатно, не чаще раза в сутки).
- Настройки: формат коэффициентов (десятичный / дробный / американский), язык (RU, EN), звук, вибрация.

### 4.7. Уведомления от бота
- Ставка рассчитана (с суммой выигрыша и кнопкой открыть).
- Бонус доступен.
- Матч из избранного начинается.
- Уведомления отключаются в настройках. Не спамить: не больше N сообщений в день.

## 5. Линия и коэффициенты

### 5.1. Источник данных
Сделать **абстракцию провайдера** (`OddsProvider`) с двумя реализациями:

1. **Реальные данные** — бесплатный тариф внешнего API (например, The Odds API или API-Football; выбери, проверь лимиты бесплатного тарифа и условия использования). Ключ — в `.env`.
2. **Генератор (mock)** — работает без ключей: создаёт реалистичные матчи из списка настоящих лиг и команд, считает коэффициенты из рейтингов команд, **симулирует лайв** (минуты идут, голы происходят по пуассоновскому процессу, коэффициенты пересчитываются, рынки временно блокируются).

По умолчанию демо должно полноценно работать на генераторе. Переключение — переменной окружения.

### 5.2. Расчёт коэффициентов
- Коэффициент = `1 / (вероятность × (1 + маржа))`, маржа настраивается в админке (по умолчанию 5–6 %).
- Для футбола — модель Пуассона по ожидаемым голам команд: из неё выводятся 1X2, тоталы, обе забьют, точный счёт, форы — коэффициенты должны быть **согласованы между собой**.
- Округление до 2 знаков, минимальный коэффициент 1.01.

### 5.3. Расчёт ставок (settlement)
- После окончания матча результат фиксируется, все ставки по нему рассчитываются автоматически.
- Правила: выигрыш / проигрыш / возврат (коэфф. 1.00 для отменённых событий и для азиатских фор «ровно в ноль») / половина выигрыша/проигрыша для четвертных фор.
- Экспресс: проигрыш любого события = проигрыш; возврат события = его коэффициент становится 1.00.
- Расчёт **идемпотентный** (повторный запуск не начисляет дважды) и в транзакции БД.
- Ручной перерасчёт из админки с логом, кто и что изменил.
- **Покрыть расчёт юнит-тестами на все типы рынков и крайние случаи.** Это ядро продукта.

## 6. Дизайн — главный приоритет

### 6.1. Подготовка (обязательно до вёрстки)
1. Через браузер изучи 10–15 референсов: современные интерфейсы спортивных ставок и спорт-приложений на Dribbble, Behance, Mobbin (запросы вроде *sportsbook app*, *betting app UI*, *sports app dark*), а также лучшие Telegram Mini Apps.
2. Сохрани в `docs/design/` скриншоты-референсы и короткий разбор: что берём (паттерны, сетка, подача коэффициентов), чего избегаем.
3. Сформулируй **дизайн-концепцию**: настроение, палитра, шрифты, сетка, стиль иконок, принципы анимации — файл `docs/design/concept.md`.
4. Не копируй интерфейс, логотип или фирменный стиль конкретного существующего букмекера. Нужен собственный узнаваемый стиль.

### 6.2. Направление стиля
- **Тёмная тема по умолчанию** (глубокий тёмно-синий/графитовый фон, не чистый чёрный) + светлая тема. Учитывать `themeParams` Telegram, но с собственной палитрой бренда.
- Один яркий акцентный цвет бренда (например, неоново-лаймовый или электрик-фиолетовый — выбери в концепции) для CTA и выбранных коэффициентов; зелёный — выигрыш/рост, красный — проигрыш/падение/LIVE.
- Лёгкие стеклянные эффекты (backdrop blur) для шапки и купона, мягкие градиенты, аккуратные тени, скругления 12–20 px.
- Шрифт: Inter / Manrope / Onest (кириллица обязательна), для чисел — моноширинные цифры (`tabular-nums`), чтобы коэффициенты и баланс не «прыгали».
- Иконки: единый набор (Lucide/Phosphor) + собственные иконки видов спорта в едином стиле.
- Логотипы команд: из источника данных; если нет — генерируемая эмблема (инициалы на цветном щите), но не пустой кружок.

### 6.3. Анимации и тактильность
- Framer Motion: переходы между экранами, появление списков (stagger), шторка купона с физикой пружины, анимация счётчика баланса.
- Нажатие на коэффициент — микро-scale + haptic (`HapticFeedback.impactOccurred('light')`), успешная ставка — `notificationOccurred('success')`.
- Skeleton-загрузка вместо спиннеров на всех экранах.
- Все анимации ≤ 300 мс для интерфейса, уважать `prefers-reduced-motion`.

### 6.4. Обязательные состояния каждого экрана
Загрузка (skeleton) · пусто (иллюстрация + действие) · ошибка (понятный текст + «Повторить») · нет сети · данные. Ни одного экрана без всех состояний.

### 6.5. Telegram-специфика
- Использовать нативные элементы: `MainButton` для подтверждения ставки, `BackButton` для навигации, `expand()` при старте, safe-area insets, цвет хедера под тему.
- Целевые размеры: 360–430 px по ширине (основная проверка — 390×844), плюс Telegram Desktop (мин. 380 px окно).
- Без горизонтального скролла страницы, зоны нажатия ≥ 44 px.

### 6.6. Брендинг
Придумай 3 варианта названия и логотипа (SVG), выбери лучший или оставь на утверждение заказчику. Сделай: логотип, иконку бота (512×512), картинку-обложку для `/start`, превью для описания бота.

## 7. Админ-панель
Отдельный веб-раздел (доступ по Telegram ID из `.env` или по логину), можно проще по дизайну, но аккуратно:
- Дашборд: пользователи (всего/DAU), ставки за день, оборот монет, GGR в монетах, топ событий.
- События: список, создание вручную, редактирование коэффициентов, приостановка рынка, ввод результата, расчёт/перерасчёт.
- Настройки: маржа, лимиты, размер бонусов.
- Пользователи: поиск, баланс, история ставок, блокировка, ручная корректировка баланса (с причиной в логе).
- Журнал действий админов.

## 8. Модель данных (минимум)

- `User` — telegram_id, username, имя, аватар, язык, настройки, реферер, created_at, флаги блокировки.
- `Wallet` — user_id, currency (`DEMO` сейчас; позже `RUB` и др.), balance (целое число в минимальных единицах, **никаких float для денег**).
- `LedgerEntry` — неизменяемый журнал всех движений: тип (bonus, bet_stake, bet_win, refund, cashout, admin_adjust), сумма, ссылка на ставку, баланс после. Баланс всегда сверяем с суммой журнала.
- `Sport`, `League`, `Team`, `Event` (статус: scheduled / live / finished / cancelled; счёт; время), `Market`, `Outcome` (коэффициент, статус, результат).
- `Bet` (тип single/express, сумма, итоговый коэффициент, статус, выигрыш), `BetSelection` (исход, коэффициент **на момент ставки**).
- `Achievement`, `UserAchievement`, `DailyBonus`, `AdminLog`.

## 9. Безопасность и качество
- Проверка подписи `initData` на каждом запросе (и срока её давности).
- Вся логика расчёта и баланса — **только на сервере**; клиент присылает только «какой исход и какая сумма», коэффициент сверяется с текущим на сервере.
- Списание ставки — атомарно, с блокировкой строки кошелька (защита от двойного списания при параллельных запросах).
- Rate limiting, валидация входных данных (zod).
- Секреты только в `.env`, `.env` в `.gitignore`.
- Логи ошибок (pino), понятные ответы API.

## 10. Задел под реальные деньги (не реализовывать сейчас)
Только архитектурно подготовить:
- Кошельки уже мультивалютные, журнал двойной записи — подключение рублей = новая валюта + платёжный провайдер.
- Интерфейс `PaymentProvider` (deposit/withdraw) — пустая заглушка.
- Места под KYC/верификацию возраста и ответственную игру (лимиты депозитов, самоисключение).
- Флаг `REAL_MONEY_ENABLED=false`, при котором любые платёжные пути недоступны.

> Важно: приём ставок на реальные деньги в РФ требует лицензии букмекера и работы через ЦУПИС; в других странах — своя лицензия. Это решается юридически до включения, агент ничего платёжного не подключает.

## 11. Порядок работы агента

Работай этапами, после каждого — коммит, скриншоты в `docs/screenshots/этап-N/` и короткий отчёт в `docs/progress.md`.

1. **Исследование и дизайн-концепция** (раздел 6.1) + брендинг-варианты. → Отчёт заказчику, ждать подтверждения стиля, если заказчик доступен.
2. **Каркас:** монорепо (`apps/web`, `apps/api`, `apps/bot`, `packages/shared`), docker-compose, БД, авторизация через initData, бот с кнопкой Mini App.
3. **Линия:** генератор матчей и коэффициентов, симуляция лайва, WebSocket.
4. **Главный экран и страница матча** — с полным дизайном и состояниями.
5. **Купон, ставки, баланс, расчёт** + юнит-тесты расчёта.
6. **Мои ставки, профиль, бонусы, лидерборд, достижения, уведомления.**
7. **Админ-панель.**
8. **Полировка:** анимации, пустые состояния, светлая тема, i18n, производительность.
9. **Проверка и сдача** (раздел 12).

### Самопроверка в браузере (на каждом этапе)
- Открывай приложение в браузере в мобильном вьюпорте 390×844 и 360×740, делай скриншоты и **сам критически оценивай их** как дизайнер: выравнивание, отступы, контраст, иерархия, «дешёвые» места. Исправляй, пока не будет на уровне референсов.
- Проверяй консоль на ошибки и сетевые запросы.
- Для проверки вне Telegram сделай dev-режим с моком `initData` (только при `NODE_ENV=development`).
- Финально — проверка в реальном Telegram через туннель (когда будет токен бота).

## 12. Критерии приёмки
- [ ] `docker compose up` поднимает всё одной командой, README описывает запуск за 5 минут.
- [ ] Бот отвечает на `/start`, открывает Mini App, авторизация проходит, пользователь получает 10 000 монет.
- [ ] Видны лайв- и прематч-события минимум по 5 видам спорта, лайв «живёт» (счёт, минуты, коэффициенты меняются).
- [ ] Можно сделать ординар и экспресс, баланс корректно списывается, после матча ставка рассчитывается, выигрыш начисляется, приходит уведомление в бота.
- [ ] Юнит-тесты расчёта зелёные, e2e-сценарий «открыл → поставил → рассчиталось» проходит.
- [ ] Сумма `LedgerEntry` по каждому кошельку совпадает с балансом.
- [ ] Двойное нажатие / параллельные запросы не приводят к двойному списанию.
